# vmap and pmap: The Bigger Picture

## Why vmap Changes Everything

In PyTorch, you write batch-aware code from day one. Every tensor carries a batch dimension, and you mentally track it through every operation. In JAX, you write code for a **single example** and let `vmap` handle batching. This is not just syntax — it's a different way of thinking.

The key insight: `vmap` is a **function transformation**, just like `jit` and `grad`. You don't rewrite your function. You transform it.

```python
def predict(params, x):
    return jnp.dot(params, x)

# Single example
y = predict(params, x_i)

# Batched — same function, transformed
batched_predict = jax.vmap(predict, in_axes=(None, 0))
Y = batched_predict(params, X_batch)
```

This composes naturally with everything you've learned:

```python
# Compiled + batched + gradient — three transformations, one pipeline
train_step = jax.jit(jax.vmap(jax.grad(loss), in_axes=(None, 0, 0)))
```

## in_axes: The Contract

`in_axes` is a tuple parallel to your function arguments. Each element says: "map over this axis."

- `0` → map over axis 0 (the batch dimension)
- `None` → broadcast (don't map — replicate across the batch)
- Nested tuples for nested pytrees

The flexibility is powerful but easy to misuse. The most common mistake: forgetting that `in_axes` applies to **arguments**, not parameters inside the function.

## pmap: vmap Across Devices

`pmap` is conceptually `vmap` where the "batch" is spread across physical devices. Each device gets one slice of the leading axis.

Key differences from vmap:
- Leading axis size must equal device count
- Communication is explicit (`jax.lax.pmean`, `jax.lax.psum`)
- Each device runs the same computation on its slice

For modern multi-GPU/TPU work, `jax.sharding` is becoming the preferred approach. But `pmap` teaches the mental model: **data parallelism is just batching across devices**.

## Sharp Edges

1. **vmap + randomness**: Each batch element needs its own PRNG key. You'll see this pattern constantly: `jax.vmap(fn, in_axes=(0, None))(keys, x)`.

2. **vmap + control flow**: Just like `jit`, Python control flow is traced. Use `jax.lax` primitives inside vmapped functions.

3. **pmap + device mismatch**: If your batch size doesn't match device count, you pad or you use `jax.sharding` instead.

## Connecting to Earlier Concepts

- **jit**: Compile the vmapped function for speed. `jit(vmap(f))` is the standard pattern.
- **grad**: `vmap(grad(f))` gives per-example gradients — useful for gradient clipping, influence functions, or analyzing data points.
- **PRNG**: vmapped functions often need vmapped keys. This is where JAX's explicit randomness really shines (no global state to get wrong).
