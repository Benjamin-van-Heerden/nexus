# Theoretical Exercise: When to Choose Rust vs Python

**Goal:** Articulate your understanding of when Rust is the right tool and when Python remains the better choice.

## Instructions

Read through the following scenarios. For each one, decide whether you would:
- **A)** Use Python
- **B)** Use Rust
- **C)** Use a hybrid approach (Python + Rust extension)

Then write 2-3 sentences explaining *why* for each choice.

## Scenarios

1. **Data Processing Pipeline**
   You need to process 10GB of log files daily, parsing JSON, filtering records, and aggregating statistics. The current Python script takes 3 hours to run.
   Answer: Assuming that the python script is already reasonably optimized, e.g. already uses numpy and other advanced data processing libraries the gains from a rust rewrite may be negligible. It all depends on the actual structure of the task. If the log files are read and parsed initially with python there could be a huge win from rewriting this in rust (keyword *could*), for aggregating statistics it probably makes most sense to just e.g. use polars in stead of pandas - could be a huge win right there. At the end of the day it comes down to isolating the inefficiencies in the script. Some parts could see significant performance improvements with a Rust rewrite, other parts may even be worse, e.g. numpy is already highly optimized c-code and "our" implementation may just be flat out worse.

2. **CLI Tool for Developers**
   You're building a command-line tool that developers will install and use to lint their code. It needs fast startup time and should work on any machine without complex setup.
   Answer: Definitely Rust, not much more to say on that. Can't expect users to install python on their machines if we need something that can be distributed + cross compilation targeting different architectures reasonably simple. Linting is also intensive, especially in large codebases. Easy. Just use Rust.

3. **Web API for User Management**
   A standard CRUD API with authentication, database queries, and JSON responses. Typical request volume: ~100 req/s.
   Answer: Python - not much more to say on that, actually anything the person who has to write it is most comfortable writing in - doesn't matter what you use. Deployment slightly easier with compiled languages, but Docker exists so yeah, use anything. FastAPI is generally a good bet.

4. **Machine Learning Model Serving**
   You trained a model in PyTorch and need to expose it via an API for real-time inference. The model itself runs on GPU.
   Answer: If it's just the serving then you may be fine just using FastAPI e.g. - the intensive inference is handled by PyTorch, we just need to serve the results. Realistically, the GPU work is going to be the bottleneck here is almost all cases so what you use to serve things shouldn't really matter.  

5. **Embedded System Firmware**
   Code running on a microcontroller with 256KB RAM, reading sensors and controlling hardware.
   Answer: Obviously Rust. Python won't even start here - not enough RAM. No brainer.

## Reflection Questions

After completing the scenarios, answer these:

1. What's the *single most compelling reason* for you personally to learn Rust? (Be specific to your work/interest)
Strong systems language in my toolbelt that I can reach into *when it is necessary*, but more than that - becoming good at rust will impose patterns on the rest of my coding philosophy that will almost definitely be useful. It's a certain kind of thinking - "is this heap, is this stack, what can we optimize?". Lots of systems primitives simply don't exist (or are exceedingly rarely necessary), in higher level languages like python - this knowledge will be indispensible.

2. What aspect of Rust's philosophy (ownership, explicitness, performance, correctness) resonates most with your experience of Python's limitations?
Basically performance and type safety.

3. What's your biggest concern or hesitation about learning Rust?
Not really, have committed to it, look forward to the challenge.
